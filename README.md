# Нагрузка Mac

Локальное приложение для строки меню macOS: общий ориентир 0–100%, процессор, оперативная память и свободное место на домашнем томе. AppKit + SwiftUI, без пакетов, веб-служб, телеметрии и сетевых запросов. В Dock значка нет. При первом запуске в строке меню только процент; выбранный стиль сохраняется при обновлении приложения.

## Сборка и запуск

Нужны Apple Silicon, macOS 13 или новее и Xcode Command Line Tools. Проверено на macOS 27 arm64, Swift 6.4.2.

```sh
cd mac-health-monitor
./build.sh
open 'build/Нагрузка Mac.app'
```

Готовый `.app` находится в `build/Нагрузка Mac.app`. Подпись ad-hoc, локальная; notarization и сертификата распространения нет. Сборка не устанавливает приложение, не включает автозапуск и не требует административных прав. После проверки `.app` можно отдельно скопировать в `~/Applications`; это не сделано сборщиком.

Нажмите процент для подробностей. В сворачиваемом разделе «Настройки» выбираются стиль (процент, значок с процентом, шкала с процентом) и интервал 2/5/10/30 секунд, по умолчанию 5. Настройки сохраняются локально в UserDefaults домена `local.zxlqr.mac-health-monitor`. Кнопка «Выйти» завершает приложение. Щелчок вне popup и Escape закрывают подробности.

## Шкалы в подробностях

Четыре полосы показывают общую нагрузку, загрузку CPU, долю занятой оперативной памяти и долю занятого домашнего тома. Все растут слева направо от 0 до 100%; рядом есть числовое значение. Под диском отдельно написано, сколько места **свободно**. Недоступные данные обозначены прочерком и подписью, а не пустой полосой с ложным нулём.

Цвет общей оценки и CPU: зелёный — ниже 50%, синий — 50–84%, янтарный — 85–94%, красный — от 95%. Повышенное/критическое давление памяти окрашивает общую оценку в янтарный/красный. Цвет памяти отражает давление, а не процент занятости; состояние также написано словами. Диск предупреждает при менее 10% свободного места, красный — при менее 5%. Цвета адаптируются к светлой/тёмной теме; данные доступны текстом и VoiceOver. Отдельных таймеров и анимации для полос нет.

Popup шириной 380 pt ограничен видимой высотой экрана. На небольшом экране и при раскрытии пояснения содержимое прокручивается, включая настройки и кнопку выхода.

Тумблер «Подробный режим» сохраняет выбранный режим. По умолчанию включён простой режим с общими показателями. В подробном под шкалами CPU и памяти видны по три приложения со значками с наибольшим расходом. Список CPU показывает долю мощности всего Mac за интервал между замерами. Список памяти показывает текущий объём физической памяти, отнесённой macOS к процессам приложения (physical footprint). В расход входят доступные для измерения дочерние процессы. Системные службы и отделённые помощники, которые нельзя связать с приложением по дереву процессов, могут оказаться вне списков. Первый замер памяти появляется сразу после открытия, CPU — примерно через секунду. Затем списки обновляются с выбранным интервалом.

## Что означает число

`нагрузка = max(CPU %, оценка давления памяти)`.

CPU — доля занятых тиков всех логических ядер между измерениями, нормированная к 0–100%. Это процент всей машины; он отличается от процентов отдельного процесса в «Мониторинге системы», которые могут превышать 100%.

Давление памяти читается из системного `kern.memorystatus_vm_pressure_level`: нормальное → 0; повышенное → 70; критическое → 100. Пороги 70/100 — выбранная шкала этого приложения, не процент Apple. Число служит понятным ориентиром текущей занятости, не универсальным «здоровьем» или результатом бенчмарка.

Если давление памяти или CPU недоступны, общая оценка выводится как `—%`; отсутствие данных не подменяется нормальным состоянием. При старте и пробуждении CPU сначала собирает базовые счётчики; первое число появляется примерно через секунду.

Память в ГиБ приблизительно равна `(internal_page_count − purgeable_count + wire_count + compressor_page_count) × page_size`, с нижней границей 0 для первого слагаемого. Файловый кэш не считается занятой памятью. Это не побайтовая копия Activity Monitor. Процент занятой ОЗУ не добавляется к общей оценке: высокая занятость сама по себе не доказывает нехватку памяти.

Свободное место — `volumeAvailableCapacity` тома, содержащего домашнюю папку; рядом указан его `volumeTotalCapacity`. В APFS пространство разделяется томами контейнера. Это не объём «доступного с очисткой» Finder и не сумма всех подключённых дисков. Диск обновляется раз в минуту и после пробуждения. При остатке менее 10% показано «мало места». **Диск не входит в общую нагрузку**, что прямо написано в popup.

## Нагрузка самого приложения и ограничения

При закрытых подробностях измеряются агрегированные Mach/sysctl-счётчики и метаданные тома. В открытом окне в подробном режиме приложение также читает счётчики процессов через libproc. Результаты хранятся в оперативной памяти. Таймер допускает 20% задержки для совместного пробуждения с системой; во время сна приостановлен. Свободное место кэшируется на 60 секунд.

Автозапуска, уведомлений и настольного WidgetKit-виджета в этом проекте нет. Интервал влияет только на CPU/ОЗУ, а не на минутный кэш диска. Приложение не изолировано App Sandbox; отсутствие сетевых запросов обеспечено его реализацией, не отдельным сетевым фильтром.

## Проверка

```sh
'build/Нагрузка Mac.app/Contents/MacOS/MacHealthMonitor' --self-test
```

Self-test проверяет формулу при нормальном/повышенном/критическом/недоступном давлении, затем реальные CPU, VM и disk API. Он не запускает постоянный UI и не меняет настройки. Результаты сборки и измерение потребления — в `VALIDATION.md`. Живая визуальная приёмка popup проводится отдельно.


Для визуальной проверки без опроса системы и изменения настроек есть отдельное настоящее окно с примером данных:

```sh
'build/Нагрузка Mac.app/Contents/MacOS/MacHealthMonitor' --preview-window --preview-state warning --preview-dark
```

`--preview-state`: `normal`, `warning`, `critical`, `unavailable`, `zero`, `full`. `--preview-expanded` раскрывает пояснение; `--preview-height 360` ограничивает высоту для проверки прокрутки. Без `--preview-dark` используется светлая тема. В этом режиме таймер не запускается, изменения Picker действуют только в окне и не записываются в UserDefaults. Закрытие окна завершает только процесс предпросмотра.
