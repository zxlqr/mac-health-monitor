# Проверка 2026-11-03

Среда: MacBook Pro, Apple Silicon arm64, macOS 27; Apple Swift 6.4.2, Command Line Tools SDK.

- Оптимизированная сборка `swiftc -O`, target arm64 macOS 13: успешно.
- Локальная ad-hoc подпись и `codesign --verify --strict`: успешно.
- Self-test формулы: normal=CPU, warning минимум 70, critical=100, unavailable=nil; успешно.
- Живой self-test: CPU в пределах 0–100, память положительна и не больше физической, свободное место положительно; успешно. JSON — `build/self-test.json`.
- При закрытом popup и интервале 5 с: после 5 с прогрева наблюдалось 25,2 с; добавилось 0,03 с процессорного времени, то есть **0,119% одного ядра в среднем**. Шесть наблюдений RSS: **29,7–44,42 МиБ**. Временный процесс измерения завершён. JSON — `build/resource-check.json`.

Показатель CPU рассчитан как изменение накопленного CPU time процесса / время наблюдения. RSS — резидентная память, не `physical footprint`; macOS меняет резидентность под нагрузкой. Это короткое наблюдение на загруженной машине, а не долговременный бенчмарк энергопотребления. Стоимость открытого SwiftUI popup этим замером не покрыта.

Диск читается максимум раз в минуту (плюс старт/пробуждение), прочие агрегированные счётчики — по выбранному интервалу. Сетевых вызовов, сторонних зависимостей, автозапуска, установки и запроса дополнительных разрешений в проекте нет.

Живую визуальную приёмку NSPopover, раскрытия формулы, системных Picker, Escape и вариантов строки меню проводит основной агент. Программный bitmap-кэш SwiftUI был признан недостаточным свидетельством отображения AppKit material; в финальном приложении функции такого рендера нет. Непроверенная визуальная приёмка не заявляется завершённой.
